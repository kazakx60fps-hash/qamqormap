# QamqorMap

Көмек қажет адамдарды, еріктілерді және координаторларды бір картада байланыстыратын веб-платформа және
Android/iOS мобильді қосымшасы. Оқу жобасы (дерекқорлар пәні). Жобаны әзірлеген: Касенов Бекнур, Қайролла Дамир. Топ: 2504.

```
HTML + CSS + JavaScript (ES modules, Leaflet)      React Native + Expo + TypeScript (mobile/)
                    ↓                                            ↓
        HTTP / REST API (JSON, multipart/form-data, SSE) — бір API
                                    ↓
                           Node.js + Express
                                    ↓
                              PostgreSQL
```

**Мобильді қосымша** — `mobile/` папкасында: іске қосу, телефон үшін API мекенжайы, APK жинау — [`mobile/README.md`](mobile/README.md);
дескрипторлар кестесі — [`mobile/DESCRIPTORS.md`](mobile/DESCRIPTORS.md); қорғау сценарийі — [`mobile/DEMO.md`](mobile/DEMO.md).

**Онлайн демо (GitHub Pages):** https://kazakx60fps-hash.github.io/qamqormap/ — статикалық нұсқа, оқу деректерімен
(кіру мен өтініш жіберу тек толық серверде). Жариялау, жаңарту және тегін толық хостинг — [`DEPLOY.md`](DEPLOY.md).

Телефонда ашу (Windows): **`IskeQosu-Mobile.bat`** → Expo Go арқылы QR-кодты сканерлеу. Әдепкіде **tunnel** режимі:
телефон компьютермен бір Wi‑Fi-да болмаса да қосылады ([`DEPLOY.md` → 3-бөлім](DEPLOY.md#3-мобильді-қосымша-expo-go--tunnel)).

Қорғауға арналған бөлек демо дерекқор: `npm run demo:setup` → `npm run demo` (Windows: `IskeQosu-Demo.bat`), кейін `npm run demo:reset`.

## Windows-та іске қосу

### Ең оңай жолы
Node.js 20+ және PostgreSQL орнатылған болса, жоба папкасындағы **IskeQosu.bat** файлын екі рет басыңыз.
Бірінші рет ол `postgres` құпиясөзін сұрап, дерекқорды, `.env` файлын жасайды, пакеттерді орнатады, демо деректерді қосады
және сайтты браузерде ашады. Келесі жолдары тек сайтты іске қосады.

### Қолмен баптау

### 1. Қажетті бағдарламалар
- **Node.js 20 немесе одан жаңа** — https://nodejs.org (LTS нұсқасы).
- **PostgreSQL 14 немесе одан жаңа** — https://www.postgresql.org/download/windows/ (орнатқанда `postgres` құпиясөзін есте сақтаңыз).

### 2. Дерекқор жасау
**SQL Shell (psql)** бағдарламасын ашып, `postgres` ретінде кіріңіз де, мынаны орындаңыз:

```sql
CREATE ROLE qamqor LOGIN PASSWORD 'qamqor_dev';
CREATE DATABASE qamqormap OWNER qamqor;
CREATE DATABASE qamqormap_test OWNER qamqor;
```

### 3. Баптау
Жоба папкасында PowerShell ашыңыз:

```powershell
npm install
copy .env.example .env
notepad .env
```

`.env` ішінде `your_password` орнына өз құпиясөзіңізді жазыңыз (жоғарыдағы мысалда — `qamqor_dev`).

### 4. Миграциялар және демо деректер
```powershell
npm run setup
```
Бұл `npm run migrate` (кестелер, шектеулер, 89 қала, облыстар, санаттар, апат түрлері) және `npm run seed` (оқу деректері) командаларын орындайды.
Екі команданы да қайта іске қосу қауіпсіз: бар жазбалар жойылмайды, демо жазбалар қайталанбайды.

### 5. Сайтты іске қосу
```powershell
npm start
```
Браузерде ашыңыз: **http://localhost:3000**

### Тесттер
```powershell
npm test
```
`npm test` API тесттерін (тіл, қате кодтары, апат оқиғалары, жеке деректер қорғауы, мобильді Bearer сессиясы, демо-кіру,
чаттың оқылу күйі, CORS) және аударма тесттерін
(үш сөздіктің кілттері бірдей, ru/en ішінде қазақ әріптері жоқ, сервердің әр коды аударылған) іске қосады.
Сайт іске қосулы тұрғанда барлық беттерді үш тілде тексеру (Playwright керек): `npm run check:i18n`.
Тесттер `.env` ішіндегі **TEST_DATABASE_URL** дерекқорында іске қосылады және оның `public` схемасын тазалайды —
сондықтан ол негізгі дерекқордан бөлек болуы міндетті (бірдей болса, тест іске қосылмайды).

Браузердегі толық сценарий (Playwright керек: `npm i -D playwright && npx playwright install chromium`):
```powershell
# тестілік базада бөлек сервер
$env:DATABASE_URL=$env:TEST_DATABASE_URL; $env:PORT=3100; npm run seed; npm start
# басқа терезеде
$env:BASE="http://localhost:3100"; node scripts/e2e.mjs
```

## Үш тіл (KK / RU / EN)
- Әдепкі тіл — қазақша. Тіл ауыстырғыш жоғарғы мәзірде және мобильді мәзірде.
- Сөздіктер: `public/js/i18n/kk.js`, `ru.js`, `en.js`; барлық компонент кілттерді `t()` / `th()` арқылы қолданады.
  Кілт табылмаса — қазақша мәтін көрсетіледі.
- Қонақтың тілі браузерде (`localStorage`), тіркелген қолданушының тілі PostgreSQL-де (`users.preferred_lang`, `PATCH /api/auth/language`).
- Тіл ауысқанда қала (URL), карта сүзгілері (URL) және формаға енгізілген мәндер сақталады; `<html lang>`, күн мен сан форматы жаңарады.
- Backend тұрақты кодтар қайтарады: `{ code, params, field_codes }` (мысалы `REQUEST_NOT_FOUND`, `MIN_LENGTH {min:5}`);
  ішкі хабарламалар `type + params` түрінде сақталып, алушының тілінде көрсетіледі.
- Қала мен облыс атаулары таңдалған тілде (`cities.name_en`, `regions`). Қолданушы мәтіндері (сипаттама, хат) автордың тілінде қалады
  және «автордың мәтіні, аударылмаған» деп белгіленеді — автоматты аударма жасалмайды.

## Табиғи апаттар
- Жаңа бағыт «Табиғи апаттар»: су тасқыны, жер сілкінісі, табиғи өрт, сел, жер көшкіні, қар көшкіні, қатты боран, құрғақшылық/аптап.
- **Оқиға** (апаттың өзі) және **өтініш** (нақты көмек) бөлек. Бір оқиғаға бірнеше өтініш байланысады:
  эвакуация/тасымал, уақытша баспана, су мен азық, киім мен заттар, қауіпсіз орын табуға көмек, еріктілерді ұйымдастыру.
  Бұрынғы өтініштер оқиғасыз жұмыс істей береді.
- Оқиға бірнеше қалаға, тұтас облысқа немесе елді мекеннен тыс нүктеге (радиусымен) қатысты бола алады.
- Оқиғаны тек координатор жасайды/жаңартады; барлық өзгеріс тарихта (`disaster_event_history`) сақталады.
  Қолданушы тек «ықтимал оқиға туралы хабар» жібереді — ол жария етілмейді, координатор қарайды.
- Белгілер: «Тексерілмеген» / «Координатор тексерді» (мемлекеттік органдардың ресми растауы емес), «Белсенді» / «Аяқталған».
- Апаттар бөлімінде 112 туралы ескерту бар. Апатқа байланысты өтінішке ұсыныс тек қауіпсіздік ережесін растағаннан кейін жіберіледі;
  мұндай өтініштерге тек «апаттағы көмекке келіскен» еріктілер ұсынылады. Эвакуация жолдары, болжамдар, «қауіпсіз аймақтар» жоқ.
- Сыртқы немесе жаппай хабарлама жіберілмейді; тек сайттағы ішкі хабарламалар.
- Демо оқиғалар «Оқу мысалы» деп анық белгіленген (жолақты баннер, картадағы сары «i» белгісі).

## Оқиғалар картасы (`/incidents`)

Қазақстанның интерактивті картасы (Leaflet + OpenStreetMap, API кілтінсіз, атрибуциясы картада көрсетіледі):
- ашылғанда бүкіл Қазақстан көрінеді; қала іздеу (KK/RU/EN атаулар), масштабтау, жылжыту, «Бүкіл Қазақстан» батырмасы;
- түр сүзгілері санымен: **Өрт · Су тасқыны · Жер сілкінісі · Авария · Басқа мәселе** (топтар `/api/disaster-types` → `groups`);
- белгіні басқанда карточка: түрі, «Координатор тексерді / Тексерілмеген», белсенді/аяқталған, аумағы (шамамен), «Толығырақ»;
- **хабарлама қосу**: картадан нүкте таңдау (немесе «Менің орным») → түрі, жақын қала, сипаттама → координатор тексеруіне;
  тексерілгенше хабарлама картада тек авторға және координаторға көрінеді (жария тізімге шықпайды);
- жүктелу, бос тізім, қате күйлері; телефонда «Карта / Тізім» ауыстырғышы, басқару элементтері бір-бірін жаппайды;
- **тайлдар жүктелмесе** (интернет жоқ, OSM бұғатталған) — сайт бұзылмайды: хабар шығады және **офлайн демо карта**
  көрсетіледі (Қазақстан шекарасы — Natural Earth, қоғамдық игілік; қалалар). Белгілер мен тізім жұмыс істей береді.
  Бұл барлық картаға (көмек картасы, оқиға беті, мобильді қосымша) қолданылады.

Картадағы барлық оқиға — **ойдан шығарылған оқу мысалдары** («Оқу мысалы» белгісі, нүктелері шамамен).
Мобильді қосымшада: Профиль немесе Табиғи апаттар → «Оқиғалар картасы».

## Ұйым кабинеті, қажеттіліктер тақтасы, көмек нәтижелері
- **Ұйым кабинеті** (`/org`, қосымшада: Профиль → «Ұйым кабинеті»):
  - бөлімдері: команда, кіріс өтініштер, жұмыстағы, аяқталған, тексеру кезегі, көмек нәтижелері;
  - сүзгілер: қала, санат, мәртебе, табиғи оқиға.
- **Ұйым координаторы:**
  - өтінішті ұйымға қабылдайды;
  - орындаушыны тек ұсыныс жіберген **өз командасының** еріктілерінен таңдайды (еріктінің қаласы мен санаты көрсетіледі).
- **Рұқсаттар серверде тексеріледі:**
  - басқа ұйымның кабинеті, тапсырмалары, контактілері және есебі жабық (`ORG_FORBIDDEN`, `ASSIGN_TEAM_ONLY`);
  - бір өтінішті тек бір ұйым қабылдайды;
  - қатар тағайындауда тек бір белсенді орындаушы қалады.
- **Тарих:** кім, қашан қабылдады (`org_accepted`), тағайындады және растады.
- **«Қажеттіліктер»** (оқиға беті):
  - өтініштер қала/аудан × санат бойынша топталады;
  - күйлер: «Орындаушы қажет / тағайындалды / Растау күтілуде / Көмек расталды»; санды басқанда тізім ашылады;
  - өтініштер саны жеке көрсеткіш; ресурс мөлшері бірлігімен бөлек көрсетіледі (мысалы, «20 бөтелке»), әр түрлі бірліктер қосылмайды;
  - сүзгілер: аудан, санат, күй;
  - жария тақтада тек жарияланған өтініштер бар.
- **«Көмек нәтижелері»:**
  - ұйым қабылдаған өтініштер;
  - алушы растаған көмек (қайта растау есептелмейді);
  - орындаушы күтіп тұрған ашық өтініштер;
  - жарияланудан алғашқы тағайындауға дейінгі медиана (есепке кірген n көрсетіледі);
  - санаттар бойынша бөлу;
  - CSV — тек жиынтық, телефон/мекенжай/хат жоқ;
  - демо деректерде «Демонстрациялық деректер» белгісі.
- **Әкімші командалары:** `npm run org -- create "Атауы" 62`, `npm run org -- add 1 user@mail.kz volunteer`, `npm run org -- list`.
- **Демо сценарийі:** [`DEMO-ORG.md`](DEMO-ORG.md).

## Мүмкіндіктер
- Тіркелу, кіру, шығу, профиль, құпиясөзді ауыстыру; серверлік сессиялар (HttpOnly cookie), scrypt хэші, CSRF белгісі, жиілік шектеуі.
- Қазақстанның 89 қаласы: қазақша, орысша және латынша іздеу, облыс бойынша сүзу, «Бүкіл Қазақстан». Таңдалған қала URL-да (`?city=`) сақталады; карта, тізім, статистика және координатор сүзгісі жаңарады.
- Көмек картасы: Leaflet, санат белгілері, топтау, таңдалған өтінішті ерекшелеу, карта↔тізім байланысы, мәтін/санат/мәртебе/шұғылдық/аудан/қашықтық сүзгілері, телефонда «Карта / Тізім» және төменгі карточка.
- Өтініштің толық жолы: жоба → тексеруде → жарияланған/түзетуге қайтарылған; ашық → таңдалды → орындалуда → растау күтілуде → аяқталды; тоқтату себеппен.
- Ерікті ұсынысы және оны кері қайтару; өтініш иесі немесе координатор орындаушыны таңдайды; координатор ауыстырады/босатады (тарих сақталады).
- Нәтижемен келіспеу (дау) және координатордың шешімі. Растау статистикаға бір рет қана қосылады.
- Чат тек өтініш иесіне, таңдалған еріктіге және координаторға; SSE арқылы жедел хабарламалар (үзілсе қайта қосылады).
- Еріктіні сәйкестендіру (қала, санат, радиус, бос күн/уақыт) «неге сәйкес?» түсіндірмесімен; қайталанған өтініштерді табу (санат, қашықтық, мәтін ұқсастығы) себептерімен.
- Фото: JPG/PNG/WEBP, 5 МБ, қайта кодтау арқылы EXIF/GPS өшіріледі, кездейсоқ файл атауы, көріну рұқсаты әр сұрауда тексеріледі.

## Жеке деректер
Нақты мекенжай, телефон және нақты координат `request_private` кестесінде сақталады. Жария API тек 250–450 м ығысқан
шамаланған нүктені қайтарады. Жеке деректер тек өтініш иесіне, белсенді орындаушыға және координаторға серверде беріледі.

## Дерекқор
Кестелер: `users, sessions, cities, volunteer_profiles, help_categories, volunteer_categories, help_requests,
request_private, applications, assignments, request_events, messages, attachments, notifications, regions, disaster_types,
disaster_events, disaster_event_areas, disaster_event_history, disaster_reports, message_reads, organizations, organization_members` (+ `schema_migrations`).

Маңызды шектеулер:
- `assignments_one_active_uq` — бір өтінішке бір ғана белсенді орындаушы (транзакция + `SELECT … FOR UPDATE`).
- `applications_one_active_uq` — бір ерікті бір өтінішке бір белсенді ұсыныс.
- `request_events_completed_once_uq` — растау оқиғасы бір рет.
- Модерация мен орындалу мәртебелері `CHECK` арқылы шектелген; бекітілмеген өтініш орындалу кезеңіне өте алмайды.

**Қашықтық:** PostGIS міндетті емес. Жергілікті PostgreSQL-де кеңейтім орнатылмаған жағдайда да жұмыс істеуі үшін
`qm_distance_km()` SQL функциясы (гаверсинус формуласы, километрмен) қолданылады.

Миграциялар `server/migrations/` ішінде, `IF NOT EXISTS` арқылы бар деректерді сақтайды:
- `001_core_schema.sql` — негізгі кестелер;
- `002_demo_key.sql` — демо жазбалардың кілті;
- `003_i18n_disasters.sql` — `users.preferred_lang`, `notifications.params`, `help_requests.content_lang` және `disaster_event_id`,
  `regions`, `cities.name_en/region_code`, `help_categories.direction`, `volunteer_profiles.disaster_support`,
  `disaster_types`, `disaster_events`, `disaster_event_areas`, `disaster_event_history`, `disaster_reports`;
- `004_mobile.sql` — мобильді қосымша үшін: `sessions.client` (web/mobile), `sessions.last_seen_at`, `message_reads` (чаттың оқылу күйі);
- `005_organizations.sql` — `organizations`, `organization_members` (coordinator/volunteer), `help_requests.org_id / org_accepted_at / org_accepted_by`, `help_requests.quantity / quantity_unit`;
- `006_incident_kinds.sql` — `disaster_types.kind` (`natural` / `incident`); жаңа түрлер `fire`, `accident`, `incident_other` анықтамалықпен қосылады, бұрынғы деректер өзгермейді.

Жаңа өзгеріс үшін келесі нөмірлі файл қосыңыз (мысалы, `007_….sql`).

## Шектеулер
- Карта қабаттары OpenStreetMap серверлерінен жүктеледі (API кілті керек емес), сондықтан интернет қажет; интернет болмаса, белгілер мен тізім жұмыс істей береді.
  Басқа провайдерді `.env` ішінде `MAP_TILES_URL` және `MAP_TILES_ATTRIBUTION` арқылы қосуға болады.
- SSE қосылымдары бір сервер процесінің жадында сақталады (бірнеше сервер үшін Redis сияқты ортақ шина керек болады).
- Қала координаттары — қала орталығының шамамен алынған нүктесі.
- Қолданушы мәтіндері автоматты түрде аударылмайды (әдейі: автордың тілінде көрсетіледі).
- Тексеру ортасында интернет болмағандықтан, карта қабаттарының (OpenStreetMap) өзі скриншоттарда көрінбейді.
